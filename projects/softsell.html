SoftSell

A single-page marketing site for a software-licence resale concept — built to see how far a landing page can be pushed on structure, motion and responsiveness without a backend behind it.

Overview

The page walks a visitor from proposition to enquiry: a hero, a three-step explanation of how selling a licence works, trust indicators and benefits, testimonials, a lead capture form, and a chat widget for questions.

It is deliberately front-end only. There is no server, no database and no payment processing — the product it advertises is a concept, and the build is about component structure, responsive behaviour and interaction quality rather than commerce.

The Problem

A landing page has one job: take a visitor who knows nothing and get them to act. Most attempts fail by saying too much at once, or by looking convincing on a laptop and falling apart on a phone.

The constraint here was to build something that reads as a real product across every screen size, with enough structure that sections could be reordered or replaced without unpicking the whole page.

Approach

STEP 01

Decompose the page into eight modules

Each region — hero, process, benefits, testimonials, lead capture, chat and the surrounding chrome — is its own component with its own props and styles. Sections can be reordered, removed or restyled independently, which is what makes a marketing page maintainable rather than one long file.

STEP 02

System-aware dark mode with an override

The theme follows the operating system by default, can be overridden by the visitor, and the choice persists between visits. Getting this right means honouring prefers-color-scheme on first paint rather than flashing the wrong theme and correcting it a moment later.

STEP 03

Validate the enquiry form on the client

The lead capture form checks its fields and reports problems inline, next to the input that caused them, before anything is submitted. With no backend to catch bad input, the interface has to be the thing that makes the state clear.

STEP 04

A chat widget structured for a real brain later

The widget runs a scripted response engine — the answers are written in advance, not generated. It is built behind a clear boundary so the script could be replaced by a live language model without touching the interface. Calling it what it is matters: it looks like a chatbot, and it is a decision tree.

STEP 05

Motion and metadata as finishing work

Framer Motion handles section transitions and hover states so movement is consistent rather than ad hoc, and React Helmet manages the document title and meta tags so the page previews correctly when shared.

Challenges

01

Claims in the README that were never measured

The repository README asserts a Lighthouse score above 95 and a first contentful paint under one second. Neither number was ever measured. They are not repeated on this page, and they should be deleted from the README or actually benchmarked — an unverified performance claim is the easiest thing in a portfolio for a reviewer to check and disprove.

02

Making a static page feel responsive

Without a server there is no real latency to hide, but also no real feedback. Every interactive element needed a considered hover, focus and active state so that clicking something visibly does something, rather than leaving the visitor unsure whether the page registered the action.

03

Animation that survives small screens

Motion designed at desktop width tends to look frantic on a phone, where elements are stacked and travel further relative to the viewport. Transitions had to be tuned per breakpoint, and kept subtle enough that they never delay reading the content.

Result

What works

  • Eight independently maintainable sections
  • Dark mode that follows the system and persists
  • Inline-validated enquiry form
  • Responsive from phone to large desktop
  • Correct link previews via managed meta tags

Known limitations

  • No backend — nothing is submitted anywhere
  • Chat responses are scripted, not generated
  • Testimonials and brand are illustrative
  • README performance claims are unverified
